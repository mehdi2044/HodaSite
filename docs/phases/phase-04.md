# Phase 04 — Cart, Customer Auth, Checkout, Orders, Offline Payment & Receipts

## Goal
A customer in any market can buy: cart → passwordless login/guest → address → transparent totals → bank transfer instructions for their market → upload receipt → admin approves → order paid. Emails at each step. Payment deadline auto-cancels.

## Scope
1. **Cart**: server-side `Cart` (cookie id; merged into customer on login), add/update/remove, market/currency lock (changing market re-quotes and warns), mini-cart drawer, cart page with quote (fees preview requires country → uses market default until address entered), stock validation on every mutation, "save for later" optional. Abandoned cart data retained for Phase 09.
2. **Customer auth** (Auth.js): email OTP (6 digits, 10 min, 5 attempts, rate limited) + magic link; account creation on first OTP; guest checkout (creates customer record flagged `isGuest`); account area: profile, addresses (per market country rules: IR province list, TR il/ilçe, CA province + postal code), orders, wishlist placeholder, language/market prefs, delete-account request. Phone stored without strict validation (basic format only, D13).
3. **Checkout** (3 steps, progress bar, autosave to cart): (1) contact + shipping address (required: first, last, email, phone, full address; optional: birth date, gender, note), (2) shipping & fees breakdown (from `quoteCart`, per-market shipping method selection if several rules are "selectable"), (3) payment method (from `Market` active methods; MVP: `OFFLINE_BANK_TRANSFER`). Terms checkbox (link to CMS page). Place order → transaction: re-validate stock, create `Order` with number `<MARKET>-<seq>` (sequence per market starting 100001), snapshots (items, fees, fx, addresses), `Reservation(kind=HOLD, expiresAt = now + Market.holdHours)`, `Payment(PENDING)`, `OrderEvent`, `holdExpiresAt`, `paymentDeadlineAt = now + Market.paymentDeadlineHours`; send `order.placed` email with bank details and the hold/deadline explained in plain language (D14).
4. **Payment page** `/[locale]/orders/[number]/pay` (also reachable from email + account): shows market bank accounts (copy buttons), amount in market currency, deadline countdown, upload receipt (jpg/png/pdf ≤ 5MB, virus-scan hook optional, stored private with signed URLs), optional reference/note → `Payment(SUBMITTED)` + `Receipt`; reservation upgraded to `kind=VERIFICATION` (no expiry until admin decides); email `order.receipt_received`. Customer can re-upload after rejection. WhatsApp/Telegram "send receipt" secondary button using market support channels (deep link with order number prefilled).
5. **PaymentProvider interface** + `OfflineBankTransferProvider`; `Integration` rows for future `stripe`, `iyzico`, `zarinpal` (stubs returning "not configured").
6. **Admin Orders**: list with filters/search/saved views, order detail (timeline, items, fees, addresses, customer, payment panel with receipt viewer/zoom, approve/reject with reason, internal notes, edit address before shipping, cancel with reason + stock release, manual "mark paid" for cash), bulk actions, export CSV. Dashboard KPIs become real (today's sales, pending verifications, new orders).
7. **Order state machine** (D15 + `NEEDS_REVIEW`) as a single module with allowed transitions + side effects (stock consume on PAID; release on CANCELLED; on approval, if hold expired and stock is gone → `NEEDS_REVIEW` + admin alert), fully unit-tested. Jobs: `expire-holds` (release HOLD reservations past `holdExpiresAt`, order stays PENDING_PAYMENT), `cancel-unpaid-orders` (deadline passed & payment PENDING → CANCELLED + email), `send-email` queue with retries. Admin can extend hold manually.
7b. **Returns data model (D33)**: `ReturnRequest`, `ReturnItem`, `StoreCredit`, `Order.parentOrderId/kind` created via migration now (no UI yet except a read-only list) so Phase 05/06 build on a stable schema. **The returned-stock states ship in the schema from day one (V-7):** enum `ReturnedItemCondition = RESTOCK | QUARANTINE | DAMAGED`, `StockItem.quarantinedQty` and `damagedQty` columns, and `StockMovement.type` gains `RETURN_RESTOCK | RETURN_QUARANTINE | RETURN_DAMAGED`. Only `RESTOCK` increases sellable stock; quarantined and damaged units are tracked separately so inventory and finance never silently absorb them.
8. **Notifications**: templates from Phase 01 used with real variables; per-market sender name; SMS provider interface + `noop` (real SMS in Phase 09).
9. Customer-facing order status page with timeline and receipt status.

## Acceptance criteria
- Full purchase flow passes as Playwright e2e in fa/IR, tr/TR, en/CA including OTP (use mail catcher `mailpit` in dev compose).
- Totals in DB equal `quoteCart` output at placement; later changing FX or rules does not alter the order.
- Reject → re-upload → approve path works; stock consumed exactly once.
- Hold expires after `holdHours` and stock becomes available to others while the order stays pending; unpaid order auto-cancels after deadline; email sent.
- Approving a receipt when stock is gone moves the order to NEEDS_REVIEW instead of overselling.
- Receipts are not publicly accessible (signed URL, 10 min).
- Admin without `payment.receipt.approve` cannot approve (server-side check tested).

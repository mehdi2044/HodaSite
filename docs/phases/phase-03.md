# Phase 03 — Pricing, FX, Fees Engine, Inventory

## Goal
Real multi-currency prices per market, admin-controlled FX (auto for TRY/CAD, manual for IRT), market markup & rounding, the configurable fee engine with simulator, and inventory with reservations ready for checkout.

## Scope
1. **Money (extends the Phase 00 Money & FX Test Gate, V-1)**: `src/lib/money.ts` — `Money` value object on `decimal.js`; add/multiply/percent/round per `RoundingRule {mode: nearest|up|down|half_even, increment: 1000|1|0.01, ending?: '.99'}`; format per locale. Decimal-only (no `number` arithmetic — enforced by lint + test); mixing currencies throws; 100% unit-tested. The gate's FX-snapshot immutability test is extended here to a real order fixture: place order → change the active rate → order totals byte-identical.
2. **FX (D06/D37)**: `FxProvider` interface; implementations: `frankfurter` (frankfurter.dev v2 API — read the official docs for the exact `latest` endpoint and symbols parameters; legacy `https://api.frankfurter.app/latest?from=USD&to=TRY,CAD` as fallback), `navasan` (`https://api.navasan.tech/latest/?api_key=…`, key from env `NAVASAN_API_KEY`; map configurable field `usd_sell` (default) / `usd_buy` → USD→IRT; value is in Toman — confirm unit against the API docs and add a unit test with a recorded sample response), `manual`. Job `fx-refresh` every 6h (configurable) + manual button. `FxQuote` history with `SUGGESTED/ACTIVE` statuses; per-market `fxMode`: `AUTO_ACCEPT` (TRY/CAD default) or `REQUIRE_APPROVAL` (IRT default: admin sees suggested vs active and clicks Accept). Sanity guard: jump > `Market.fxMaxJumpPercent` (admin-editable per market; default 5%) never auto-applies → alert. `FxOverride` with date range + note wins while valid. Stale warning badge if active rate older than `fxStaleHours`. Provider failure → keep last ACTIVE + `SystemAlert`. Admin page Pricing → FX: per currency card (active rate, suggested rate, source, last fetched, accept button), history chart, manual entry, overrides, provider status.
3. **Pricing pipeline** per architecture §3.3 (base = `SiteSettings.finance.pricingBaseCurrency`, USD): `getDisplayPrice(variant, market)` with cache (15 min, tag `pricing`), `MarketPrice` manual override editor (per product or variant, per market, date range), compareAt handling, "price includes tax" flag per market (display label). Product page & listing use it.
4. **Fees engine** per D17 — **fully data-driven (V-3): adding, editing, disabling or re-scoping a fee rule NEVER requires a code change, migration or deploy.** Methods are a fixed, versioned set of calculators in code; everything else (which rules exist, their scope, params, priority, validity, on/off) is rows in `FeeRule` edited from admin and takes effect on the next quote (cache tag `fees` invalidated on save). If a genuinely new *calculation method* is ever needed, that is a code change + ADR. Admin CRUD with method-specific param forms:
   - FIXED `{amount}`; PERCENT `{percent, of: subtotal|subtotal_plus_shipping}`; PER_KG `{perKg, minKg?}`; WEIGHT_BRACKET `{brackets:[{uptoKg, amount}], extraPerKg}`; VALUE_BRACKET `{brackets:[{uptoAmount, amount|percent}]}`; PER_ITEM `{amount}`.
   - scope: market + optional province/city/postal prefix + optional categories; priority; min/max; absorb; taxable; validity dates; active.
   - `computeFees()` pure function with deterministic ordering: SHIPPING → CUSTOMS → SERVICE → TAX (tax can be configured to apply on subtotal, or subtotal+shipping+customs).
   - Chargeable weight = max(actual, volumetric = L×W×H/`Market.volumetricDivisor` (default 5000)).
   - **Simulator** page: pick market, address fields, add items (variant + qty) → shows fee lines and which rule matched; "explain" mode.
   - Seed rules per `MASTER_SPEC` §3 example (TR domestic shipping min 150 TRY; IR shipping per kg; CA shipping bracket + customs 8% + tax placeholder 13%; service fee 2% inactive).
5. **Inventory & cost basis (D32)**: `Warehouse` (seed: Istanbul), `StockItem`, `Lot`, `StockMovement` (immutable, lot-linked), `Reservation` (kinds HOLD/VERIFICATION); admin: stock per variant in product editor with a simple "receive stock" form (qty, unit cost, currency, date → creates Lot + IN movement; FX snapshot to TRY/USD), Inventory page (adjust with reason, movement history, lots view, low-stock threshold per product/global, CSV import of stock with cost). COGS function `cogsForSale(variant, qty)` FIFO (average optional) unit-tested — used by Phase 06. Availability = onHand − activeReserved; storefront shows In stock / Low stock (≤ threshold) / Out of stock; size chips disabled when 0. Job `expire-reservations` (every minute) — reservations are created by Phase 04 but the mechanism ships now with tests.
6. **Cart preview API** (internal): `quoteCart({marketId, items, address?})` → subtotal, fee lines, total (used by Phase 04). Unit-tested against the seeded rules.

## Acceptance criteria
- Same product shows correct IRT/TRY/CAD prices with market markup and rounding; accepting a suggested Navasan rate (or a manual override) updates IR prices within 15 min (or immediately after "clear pricing cache").
- A Navasan response with a 12% jump is NOT auto-applied; alert visible; admin can accept explicitly.
- Receiving 100 pcs at 1000 TRY creates a Lot with TRY original cost and USD/TRY snapshots; FIFO COGS test passes.
- Fee simulator reproduces test cases in `08_TEST_CHECKPOINTS_FA.md` CP2-03..05 exactly.
- Turning a rule off removes it from quotes; scope specificity works (Istanbul rule beats Turkey rule).
- Reservation expiry releases stock; concurrent reservation test (two transactions, one unit) allows only one (D38: `SELECT … FOR UPDATE` in fixed order + check constraint `onHand - reserved >= 0`); a third test with 20 parallel workers on 5 units results in exactly 5 successes.
- Unit test coverage for `money`, `fx`, `fees`, `inventory` ≥ 90% lines.

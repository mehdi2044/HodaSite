# R3a — shared shoppable scenes, publication and private preview

Recorded before implementation. Implemented against docs v1.2 / D-numbers touched: D09, D10, D21, D23, D24, D31, D40, D70, D74, D77, D78. Base PR69; no merge authorization.

R3a and R3b implement the whole R3 contract together: R3a owns shared scene validation/resolution, real admin form/private preview and the existing Homepage draft/history/schedule/rollback lifecycle; R3b owns every selected MODA4 homepage block and real campaign/popup/video/discount/policy display. Neither branch alone closes AC01–18 or MODA01–14. COMPOSITE depends on R4 cutout/geometry; it must remain honestly unavailable until those real references validate. R4/R7a then consume the same scene contract. No duplicate pricing/cart/CMS backend or provider is introduced.

- Add a version1 PHOTO/COMPOSITE contract to existing content/outfits: stable scene/piece IDs; separate READY desktop/mobile media and bounded fit/focal/anchors; real product/color and optional real preferred Variant; localized alt/title; no amount input. A PHOTO may contain1–12 pieces (safety bound independent from4 fitting pieces). Reference relations, active catalog/market, media and image match are checked server-side under catalog→Media locks. PHOTO publication requires explicit authorized visual confirmation tied to actual scene media, color and garment reference images. Server-generated match fingerprints ignore price-only changes; arbitrary submitted confirmation stamps are never trusted. Catalog/media changes invalidate visual matches and trigger a truthful review fallback rather than misleading buy labels.
- Resolve live variant/stock/market Decimal prices through existing pricing/quote contracts. Present a genuine from/range before size selection, exact real Variant thereafter, unavailable instead of zero/fabricated USD. Reuse atomic cart for add-all; historical orders stay immutable. Public view objects do not expose private author/confirmation or draft data.
- Additive Homepage publication metadata and immutable AuditLog-backed content revision snapshots only, authorized by D77. Existing rows remain published legacy content without backfill/rewrite. New market draft rows do not shadow the published global fallback. Version conflicts preserve prior content; every successful draft/publish/schedule/rollback is audited inside its transaction. Rollback revalidates old references and restores content only. The existing append-only AuditLog stores versioned blocks; this avoids a parallel history store. Retain nullable columns, revisions, media and commerce history on compatible code rollback.
- Scheduled publication uses the existing DB Job/cron worker. It must recheck current actor permission/scope, row revision, live catalog/media and photo match at execution. Invalidated schedules fail visibly; replay never duplicates publication or financial effects. No separate worker or paid call.
- Draft preview is authenticated, scoped, private/no-store/noindex, excluded from PWA/CDN. Same real renderer/resolver serves admin preview and publication. Unsaved form preview uses authorized origin/nonce and bounded async ordering; current saved revision is observed within2s and public/price changes within5s/focus after successful invalidation, measured in scratch tests. Failure retains last successful build/view.
- Extend purge/reference retention to both published/draft snapshots, mobile/reference media and revisions, including trash/history. Local and S3 restore must preserve the additive fields/tables. Retained owner data is never reset, seeded or restored over.

Verification required: real visual form→private draft→save/reload→publish→already-open storefront; all three languages and desktop/mobile anchors/crop/contain; real current price/FX/stock/variant transitions; PHOTO mismatch/COMPOSITE gate; scope/foreign references/conflicts/media deletion/publication races; scheduled invalidation/idempotence; rollback vs immutable orders; no draft leak/PWA cache; Local/S3 restore.

# گزارش بازبینی برای ChatGPT — درخواست نظر دوم

> مهدی: این متن را در ChatGPT پیست کن و بگو: «این گزارش مدیر پروژه (Claude) دربارهٔ پروژهٔ من است. لطفاً به‌عنوان معمار ارشد نقدش کن: کجا اشتباه است، چه ریسکی جا افتاده، چه چیزی را ساده‌تر/بهتر می‌کنی؟ جواب مختصر و اولویت‌بندی‌شده بده.»

---

## ۱. پروژه در یک پاراگراف
فروشگاه آنلاین پوشاک (زنانه/مردانه/بچگانه) با فروش در **ایران، ترکیه، کانادا** و رابط **فارسی/ترکی/انگلیسی**. عملیات از ترکیه. قیمت پایه USD، نمایش به تومان/لیر/دلار کانادا. پرداخت نسخهٔ اول آفلاین (واریز بانکی + آپلود فیش + تأیید ادمین). حمل چندمرحله‌ای (بین‌المللی + داخلی) قابل تنظیم برای هر کشور. موتور هزینهٔ قابل تنظیم (حمل/مالیات/گمرک/خدمات). پنل ادمین کامل با «همه‌چیز قابل ویرایش» (نام، لوگو، تم، منو، صفحات، ترجمه‌ها). بعداً: حسابداری مدیریتی، CRM/وفاداری، AI (ورود اطلاعات → دستیار خرید → جست‌وجوی تصویری → پرو مجازی). تیم: مالک غیربرنامه‌نویس + Claude (مدیر پروژه/معمار) + Codex (کدنویس). مهدی هر چند فاز یک‌بار تست دستی می‌کند.

## ۲. تصمیم‌های کلیدی من (Claude)
1. **یک اپ Next.js** (App Router) شامل فروشگاه + ادمین + API، Prisma + PostgreSQL 16، Tailwind + shadcn/ui، Docker Compose روی یک VPS (Hetzner) با Caddy. نه Monorepo چند اپ، نه NestJS جدا، نه Redis/Meilisearch در MVP (Postgres FTS + جدول Job).
2. **ارز پایه USD**؛ **نرخ تومان دستی از ادمین** (چون APIهای رایگان نرخ رسمی می‌دهند نه بازار آزاد)؛ TRY/CAD از frankfurter (رایگان، بدون کلید)؛ Snapshot نرخ در سفارش؛ ضریب بازار و گردکردن قابل تنظیم.
3. **Fees Engine** با Scope (کشور→استان→شهر)، ۶ روش محاسبه، min/max، absorb، اولویت، شبیه‌ساز.
4. **پرداخت آفلاین** با Provider Interface، مهلت پرداخت + لغو خودکار + رزرو موجودی.
5. **Shipping Workflow** با Leg Template به‌ازای هر بازار.
6. **Settings/Theme/Menus/Pages/Translations در DB** → همه‌چیز از ادمین.
7. **بکاپ**: pg_dump شبانه + media + off-site + صفحهٔ ادمین با Backup/Download/Upload/Restore (MFA + بکاپ امنیتی قبل از ریستور) + تست خودکار هفتگی ریستور.
8. **۱۲ فاز، ۵ Checkpoint**: Foundation → Settings/CMS → Catalog → Pricing/Fees/Inventory → Checkout/Payment → Shipping/RBAC/Backup → AI Data Entry → SEO/PWA → Finance → CRM/Loyalty → AI Agent → Visual/Try-On/App.
9. **RBAC + Scope + Overrides + Audit append-only + MFA** برای owner/admin.
10. AI فقط پشت Gateway با بودجه و Kill switch؛ خروجی AI بدون تأیید انسان منتشر نمی‌شود.

## ۳. ریسک‌هایی که خودم می‌بینم
- دسترسی کاربران ایرانی: هاست/CDN/ایمیل باید از ایران باز شود؛ ایمیل OTP به دامنه‌های ایرانی باید تست شود (fallback پیامک در فاز ۹).
- قوانین: CASL کانادا، KVKK/e-Fatura ترکیه، مالیات استانی کانادا — کد قابل تنظیم است ولی اعداد را حسابدار محلی باید بدهد.
- Restore از داخل خود اپ (اپ در حال اجرا دیتابیس خودش را بازمی‌گرداند) — با job runner جدا و maintenance mode حل کردم ولی حساس است.
- Codex ممکن است Scope خزش کند یا UI پیش‌فرض بدهد؛ با AGENTS.md و acceptance criteria سخت کنترل کردم.
- تست دستی فقط هر ۲–۳ فاز: ریسک انباشت باگ؛ جبران با تست خودکار اجباری هر فاز.
- تولید PDF فارسی RTL در کانتینر (فونت/شکل‌دهی) معمولاً دردسر دارد.
- Auth.js با OTP ایمیل + Guest + merge سبد: جزئیات session نیاز به دقت دارد.

## ۴. سؤال‌های مشخص از تو
1. آیا «یک اپ Next.js» برای این حجم کافی و درست است، یا از ابتدا ادمین را جدا می‌کردی؟ چرا؟
2. برای نرخ تومان، راه بهتری از ورود دستی روزانه می‌شناسی که پایدار و قانونی باشد؟
3. مدل Fees Engine (Scope + Method + Priority + absorb) چیزی کم دارد؟ (مثلاً هزینهٔ بر اساس تعداد بسته، یا Free-shipping threshold به‌عنوان promotion vs fee)
4. رزرو موجودی با مهلت پرداخت ۴۸ ساعته برای پرداخت آفلاین: بهتر است رزرو کنیم یا فقط هشدار بدهیم؟
5. برای فاکتور PDF چندزبانه/RTL چه ابزاری را در Node/Docker مطمئن می‌دانی؟
6. ترتیب فازها: آیا Finance (فاز ۸) باید قبل از SEO/PWA (فاز ۷) باشد؟ یا AI Data Entry (فاز ۶) زودتر؟
7. چه چیزی در این نقشه «over-engineering» است و باید حذف شود؟
8. چه چیزی جا افتاده که در ۶ ماه اول پشیمانمان می‌کند؟
